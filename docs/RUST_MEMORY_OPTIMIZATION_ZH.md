# Rust 配置内存优化与 Linux 验证

本文是早期 Rust 控制层配合外部内核的历史测量；不能用这里的二进制/RSS 数字描述当前完整发行包。当前默认 Rust 数据层及 preview.2 功能见 [项目首页](../README.md)。

2026-10-02，继续上一轮 Linux 复验找到的内存优化点，把内核配置生成改成借用用户表并流式写候选文件。在美国测试主机的独立目录重新构建、测试，并用上一版二进制进行同条件比较。原 Go 代码和生产服务入口保持原有版本。

## 这次实际改了什么

原路径先生成用户 `Vec<Value>`，嵌套拼装完整 JSON，再编码成完整字节数组，用户信息会形成多份临时对象。新路径用借用的 `Serialize` 视图直接写候选文件，使用 64 KiB 缓冲；公开 `build` 仍返回 `Value`，兼容已有调用者。凭据借用原字符串，用户 ID 在序列化时写出，不额外保存全部名称字符串。

大小限制针对**编码后的 JSON 字节**，仍为 16 MiB。转义导致的膨胀会计入限制。候选文件唯一创建、Unix 0600 / 目录 0700、失败清理、flush/sync、外部 `sing-box check`、检查成功后激活和旧配置恢复顺序均保留。默认和不支持的功能处理没有放宽。

## 实测收益与代价

以下 RSS 为 **Rust 控制程序**，外部 sing-box 单独统计。环境：Debian 13.5、ARM64、Rust 1.98.1、sing-box 1.14.0；HTTPS 面板、协议客户端和 origin 全部回环监听。用户/面板凭据为合成数据，证书原地读取。两版顺序运行，宿主仍有其他服务。

| 指标 | 上一版 | 流式版本 |
| --- | ---: | ---: |
| 二进制字节 | 3,676,088 B | 3,741,624 B |
| 10000 用户，60 秒 RSS 中位数 | 29.70 MiB | 6.25 MiB |
| 10000 ↔ 20000 用户，6 次更新后 VmHWM | 58.28 MiB | 12.62 MiB |
| 6 次更新后恢复 10000 用户，RSS | 42.83 MiB | 12.08 MiB |
| 控制程序线程 | 2 | 2 |
| 60 秒窗口 CPU，按一颗核计算 | 0.083% | 0.116% |

本次同条件 RSS 高水位降低 **78.3%**。表中使用内核报告的累计高水位 VmHWM，覆盖启动及六次更新；10 ms 间隔采样实际见到的更新峰值为 58.28 / 12.24 MiB，流式版的 VmHWM 高于定时采样见到的峰值，故以较高值报告。二进制增加 65,536 B（1.78%），这是本轮减少内存的体积代价。CPU 原始增量分别为 5 / 7 ticks，tick 为 10 ms；不能用这个短窗口声称稳定的 CPU 降幅。用户数量是配置表规模，不能当作实际在线连接数。

### 分配器探针

仓库新增 `cargo bench -p node-kernel --bench config_memory --locked`，每组 3 次，比较**当前代码的兼容 DOM 路径**与**当前流式路径**。输入提前创建；统计请求的活跃堆字节，不含输入、分配器元数据、文件 sync 和外部配置检查。结束时受测分配回到 0，只是这段探针的释放检查。

| 用户数 | 最终 JSON | 当前 DOM 峰值 | 流式峰值 | DOM / 流式分配次数 |
| --- | ---: | ---: | ---: | ---: |
| 10000 | 619,107 B | 7.936 MiB | 0.203 MiB | 50,047 / 5 |
| 20000 | 1,249,107 B | 15.870 MiB | 0.344 MiB | 100,048 / 5 |

带计数器的中位耗时：10000 用户 14.767 / 2.007 ms；20000 用户 25.980 / 4.187 ms。固定执行顺序且包含计数器开销，不是整机 CPU 或吞吐测量。

上一轮旧构造器的临时堆峰值 20.51 / 41.05 MiB 保留在 [Linux 复验报告](RUST_LINUX_RECHECK_ZH.md)。此处 DOM 数据属于改后的兼容入口，不把它标成上一版基线；实际进程前后收益以上方二进制对照为依据。

## 功能与稳定性验证

- Windows 本地及 Linux release workspace 各 **76 项通过**；Linux 显式真实 VLESS 集成 **1 项通过**；严格 clippy 与格式检查通过。
- **9 项 CLI 检查通过**：认证拉取、实际 VLESS 内容、304 保持原内核、用户轮换、未支持限制拒绝、内核退出恢复和 SIGTERM 资源清理。本次停止约 18 ms。
- 新旧构造器 **108 组完整 JSON 逐字节一致**，涵盖 VLESS 明文/TLS、Trojan TLS、IPv4/IPv6/默认监听、日志级别、空/单/大量用户、极值 ID 和 Unicode/转义密码；**19 组错误类型与文本一致**，无效流式配置不写输出。
- 新增回归覆盖编码后恰好 16 MiB、超出 1 字节、短写、输出错误，以及转义超限时旧监听器/用户仍可用、部分候选文件被清理。真实文件 flush/sync 失败没有直接注入；该路径做了静态审查，不夸称测试覆盖全部磁盘故障。
- 两版各 **6 次 10000 ↔ 20000 用户更新**；新 UUID 先证明更新前被拒绝，再等待更新后的真实响应；上一轮 UUID 被拒绝，保留用户可访问。每次稳定后只有 1 个配置文件，控制 FD 回到 10。
- 流式版本 **256 条代理连接保持 10 秒，256 条响应完整**；并发 8、**1024 次 × 256 KiB** 内容完整；控制/服务端内核 FD 回到初始值。此次回环传输为 141.02 MiB/s，包含 Python origin、客户端和共享主机成本，没有配对旧版本吞吐对照，不据此声明 TCP 提速或最大承载。
- **真实 VLESS TLS 与 Trojan TLS 客户端通过**：使用系统证书信任和正确 server_name；错误主机名被拒绝；新凭据更新前被拒绝、更新后收到真实内容，移除的旧凭据被拒绝。Trojan 补测中文、引号、反斜杠和换行密码。证书及私钥未复制到交付包。
- 新鲜独立静态审查绑定最终 **45 个 Rust/build 文件**，未发现确认的阻断问题。测试/基准另有执行日志；资源探针自检，不冒称由审查者执行。
- 结束后本次 Rust/sing-box 测试进程为 0，7 个既有服务的 PID/状态、全局 hosts 和旧二进制哈希与前测一致。

## 尚未解决和下一步

**同端口更新仍然会中断连接。** 本轮每版更新时保持的 64 条连接全部中断，0 条完成原响应。流式生成减少配置内存，没有改变内核 stop/start。下一步优先核验按用户增量更新的内核能力，并以正在传输的连接、新增/删除用户的认证边界和失败恢复进行验收；不只检查进程存活或 API 成功返回。

数据转发仍由外部 sing-box 完成，Rust 是控制层。计费及可靠上报、限速和设备限制、其他协议/路由、多节点、持久恢复、真实生产面板、最大容量和长期运行仍待完成。60 秒和六轮更新不能证明长期无泄漏。实验没有替换生产程序，也没有 Git 提交、推送或发布。

## 复现与交付

```bash
cargo fmt --all -- --check
cargo test --workspace --release --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo bench -p node-kernel --bench config_memory --locked
SINGBOX_TEST_BINARY=/absolute/path/to/sing-box cargo test -p node-runtime --release --test real_singbox --locked -- --ignored --nocapture --test-threads=1
```

配置生成、边界与生命周期回归留在 `crates/node-kernel/tests` 和 `process.rs`；独立分配器探针在 `crates/node-kernel/benches/config_memory.rs`。更长的 HTTPS/TLS/更新测量在本次隔离主机执行，输入规模/轮询/采样间隔和原始数据见 [rust-memory-20261002.json](../benchmarks/results/rust-memory-20261002.json)。

原始测试日志、探针、前后读回、配对资源和认证结果保存在 `.Codex/evidence/memory2-linux/`；证据包 25,222 B、28 个成员均核对哈希。干净源码和 Linux ARM64 包另行交付，编译源码清单与二进制 SHA-256 绑定。Linux 包需要 ARM64 GNU、glibc 2.39+、libgcc_s；sing-box 单独提供。交付包不含 `.git`、`.Codex`、缓存、面板 Token、SSH 密码、生产证书或私钥。
